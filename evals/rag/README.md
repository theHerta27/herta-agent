# RAG 评测题集 v1（尚未运行）

28 题：13 个可回答、4 个跨段、7 个资料不足、4 个无需检索。dev 17 题，check 11 题。使用当前人工整理的 corpus，不加入项目笔记或新语料。

每条包含 question、should_retrieve、required_evidence、supporting_context、expected 和 forbidden。required_evidence 引用 K 单元，不绑定将来生成的 chunk id；跨段题要求各单元均有证据。supporting_context 表示有助于解释不足的相关资料，不意味着能回答所求细节。无需检索题不计入检索 Recall 的分母。

两组实验分开：

1. 直接检索：绕过聊天模型，用题目文本查索引，记录原始 top-k 和过滤后返回项；计算必需证据覆盖率、跨段全部命中率、片段总长度。单元被多个重叠 chunk 命中只计一次。
2. 正式聊天：记录模型是否调用 search_knowledge、实际查询、得到的 chunk id、最后引用和回答。判断应检索是否检索、无需检索是否误触发、引用是否来自本轮实际结果、结论是否受支持、资料不足是否明确说明。

dev 用于选择切分/top-k/阈值。冻结配置后才报告 check；不要依据 check 的失败继续调参后仍声称它是未见数据。题目公开可读，并且编写者看过 corpus，因此这不是盲测或大规模泛化成绩。知识文本中的覆盖范围说明有助于拒绝无依据回答，但不能据此证明系统能识别任意未知问题。K10/K11/K12 等尚无直接题目的单元也意味着题集不是全覆盖验收。

资料不足不等于相关片段应全部为零：Q17 可命中研讨会，但仍不能知道年龄；Q19 可命中理论说明，但没有完整公式。向量阈值无法独自判定可回答性。检查同类干扰片段、结果排序以及最终是否越过证据范围。

MockTransport/固定向量仅验证工程正确性；真实 Embedding 的检索报告必须用真实模型生成的文档和查询向量。模型生成质量要记录实际聊天模型、参数和重复运行差异，不能把 ScriptedProvider 的通过率当作真实端到端成绩。

交付验收：工程与52项回归必须通过；检查集的4个可回答、2个跨段、3个资料不足、2个无需检索场景逐题报告，不用小样本百分数包装成熟度。跨段题只有全部必需证据都命中才算完整成功。所有展示的来源引用必须可解析；语义正确性最终人工核对。任何未达预期的检索、触发或生成结果都列为未通过案例，不用端到端一句回答掩盖某层失败。真实服务未选定时，不预先填入分数、阈值或通过成绩。
