# 从聊天整理并保存 Markdown

## 使用

1. 将两份短 UTF-8 Markdown 放到普通资料文件夹，例如桌面的“学习资料”。不要选择源码仓库、系统目录或含敏感配置的目录。
2. 启动 Herta，点击输入框上方的“选择资料目录”，选择文件夹并允许聊天读取。这里的授权不会包含其他目录。
3. 发送：“读取 asyncio.md 和 task.md，整理复习提纲，保留文件名和行号来源，保存到复习/asyncio提纲.md，先给我预览确认。”
4. 查看聊天中的完整生成正文，点击“确认保存笔记”，在原生对话框确认。取消不会写入；目标存在时拒绝覆盖。
5. 聊天显示实际执行收据和目标内容，并在原会话请求 Herta 查询状态、读取目标后回报。核对请求被拒绝时，保留“让 Herta 核对结果”按钮。未知聊天状态应先通过既有“核对状态”恢复，避免重复请求。

## 实际实现与复用

基线为 Herta `d36a8ad`，没有新增第三方依赖，没有移植上游 Runtime。

| 环节 | 使用的已有实现 | 本次接线 |
|---|---|---|
| 目录范围 | WorkspaceService、WorkspaceBridge、原生目录与共享确认 | 输入框旁提供入口；无授权时仍允许发现空目录列表 |
| 资料读取 | read_workspace_text、既有上下文与 Agent Loop | 不新增文件服务；由模型选择文件和整理正文 |
| 笔记暂存 | DocumentService.note → FilePlans.publish | 普通目录可生成新 Markdown；Vault 面板保留原约束 |
| 预览与审批 | FilePlans、原生确认、FileJobs | 将正文与实际暂存字节绑定，聊天展示并调用同一确认入口 |
| 结果查看 | 同一 FileJobs、受共享授权控制的 read_text | 按方案直接查询旧任务，读取实际目标并核对完整字节 |
| 保存后回报 | 同一 ChatStore.send、原会话和 Agent Loop | 可见核对请求携带方案 ID；保留草稿，历史恢复不自动发送 |

资料和生成内容属于外部数据，不可授予目录、执行或审批权限。关闭共享后，任务状态与结果读取都拒绝访问。生成笔记最多10,000字符；读取预览最多400行/10,000字符，截断明确提示。路径保护、执行取消、收据和撤销沿用已有实现。

预览有效期10分钟，授权版本或目录身份变化时，既有执行器拒绝保存，需要重新生成。当前未执行卡片可能仍显示“待确认”，有效性最终由原生确认后的执行器复核；这项显示问题不允许过期写入。
