# 文件工作台v1设计

日期：2026-10-12。源码基线：`abd7835` / `phase-6-ui`。状态：书面设计待用户审阅，尚未开始产品实现。

## 目的与范围

让Herta从陪伴聊天扩展到处理实际文件任务。首次交付的成功标准是：用户选中一个目录，浏览/搜索/读取文本，生成具体整理方案，看清每个变化，确认后执行，取消未完成部分，重开看到真实收据，需要时撤销未被后续修改的动作。

用户已明确最终目标、Hermes工程参考、Cyrene功能参考和仅本地验收。下一批选择目标材料中的“安全操作文件”。假设首次重点是下载资料和学习文件，不自动扫描整台电脑。

支持本地普通文件的复制、移动、批量改名和必要的子目录创建。改名就是同目录内移动。支持按类型整理和用户指定目标子目录/名称前缀。文本读取先覆盖UTF-8/UTF-8 BOM的Markdown、TXT、JSON与常见源码文本。PDF/Office正文解析、内容编辑/覆盖、原文件删除、整目录搬迁和跨授权根目录移动在后续批次实现，界面明确说明格式与边界。

## 方案选择

| 方式 | 优点 | 代价 | 选择 |
| --- | --- | --- | --- |
| 自研目录范围与不可变方案服务，Agent只提出方案，界面确认后由确定性任务执行 | 复用现有Python/SQLite/Electron，动作与实际结果可追溯，后续文档写入可复用 | 需实现文件快照、收据、取消和撤销 | 推荐 |
| 直接让模型调用任意shell/file工具 | 上手快 | 很难把用户确认精确绑定到路径和字节，撤销与重试语义不稳定 | 首版不采用 |
| 引入独立GUI/File Agent或通用自动化框架 | 可快速取得较多能力 | 增加第二个运行体系，当前文件任务不需要鼠标坐标或视觉模型 | 后续仅作为适配器评估 |

## 用户流程

主窗口增加“文件”，打开独立工作台弹层，表格有足够空间显示前后路径，保留原聊天状态。打开时停止录音/朗读；关闭弹层不停止已确认的文件任务。用户点击“选择目录”调用主进程原生文件夹选择器；取消选择不新增授权。工作台显示完整所选目录、允许的操作和撤销限制。

列表显示当前子目录中的普通文件/目录、类型和大小；有面包屑、名称搜索、选择框和文本预览。“按类型整理”把选中文件映射至文档/图片/音频/视频/压缩包/其他；“复制/移动/改名”允许填写相对子目录或名称前缀。没有勾选项时不自动全选。大目录或搜索达到上限时显示受限提示和继续缩小范围的方法，不把截断结果称为全部文件。

预览表逐项列出操作、原位置、目标位置及冲突。尚未确认时不创建输出目录或修改文件。冲突方案可以看，但执行按钮禁用，用户需要调整并生成新方案。创建预览不代表开始执行。

点击“确认并执行”后，Electron从后端重新读取不可变方案，在原生确认框显示目录、动作总数和完整前后路径。默认按钮为取消。确认的方案摘要和当前目录授权版本随请求提交；不同内容、过期方案、重复点击或已撤销范围均不能启动新的执行。

执行区域显示逐项真实结果和“停止文件任务”。关闭工作台/聊天停止不隐式撤销已经完成的文件动作；文件任务的停止按钮明确取消该任务，完成当前可中断步骤后不再开始下一项。显式退出Herta请求取消并等待自管任务清理。聊天Run只负责读文件/提出方案，不承担这个确定性执行队列。

历史保留完整方案、确认时间、每项收据和未完成原因。撤销按钮先展示逆向变化，并再次使用原生确认框；只撤销与收据仍匹配的动作。已经被编辑的目标、被占用的原路径或多出的目录内容会成为明确冲突，不覆盖。

## 授权与共享范围

目录只能通过Electron文件夹选择器注册成不透明`root_id`。模型与renderer不能提交任意绝对路径来授予范围。所选目录及其身份信息在本地独立数据库保存，可随时移除授权；授权撤销使未执行方案失效，并请求停止当前文件任务。

默认选择目录只用于本地文件工作台。单独的“允许聊天读取并规划此目录”开关才让Agent读取该目录中的文件并提出计划。开关说明：被聊天工具读取的文本会进入该轮上下文，真实聊天时会发给配置的模型服务。本地浏览、确定性整理和预览不调用模型。可把文本预览手动加入现有聊天草稿，并在发送前看到来源与内容。

聊天工具提供`list_workspace_roots`、`list_workspace_files`、`search_workspace_files`、`read_workspace_text`、`propose_file_plan`。Handler每次检查当前目录授权与聊天开关；不能因ToolSpec标记只读就跳过目录检查。模型可以持久化待确认方案，不能确认、执行或撤销文件动作。副作用策略只允许本次注册的`propose_file_plan`身份，不对任意同名工具、MCP或shell开放。

文件内容以数据标记进入上下文，不能改变Persona或授权。文件列表不给模型绝对本机路径。纯文本读取有大小/行数限制，标注截断位置。提出方案工具只返回plan_id、摘要、数量和少量示例；完整动作保存在本地并由工作台读取，避免100项方案突破工具结果预算。

## 文件边界与限制

- 本轮只支持本地文件系统，不接UNC、设备路径和NT命名空间；原始字符串在任何resolve/IO之前检查。
- 根目录必须存在，不能是磁盘根或SystemRoot指向的目录及其后代；Windows映射的网络驱动同样拒绝。注册时保存根目录身份；执行前验证它仍是同一目录。
- 相对路径拒绝绝对路径、`..`、ADS冒号、Windows保留名、非法文件名字符及尾随点/空格，按Windows大小写规则识别重名；相对路径和最终本地路径均最多240字符，目录层级最多16。
- 不跟随符号链接、junction/reparse point；遇到目录祖先或文件被替换即停止受影响动作。修改计划不支持多硬链接普通文件。
- 不扫描、读取或规划修改`.git`、`.ssh`、`.aws`、`.codex`、`.agents`、`.venv`、`.local`、`node_modules`目录；拒绝名称`.env`、`.env.*`、`credentials`、`credentials.json`、`id_rsa`、`id_ed25519`与后缀`.pem`、`.key`、`.pfx`、`.p12`。这是明确的首版产品范围列表，不宣称识别了所有秘密文件或构成OS安全沙箱。
- 当前目录最多返回1000项；名称搜索深度最多8、最多考察5000项、最多返回200项，始终返回`truncated`。
- 文本文件最多1MiB，单次最多400行/20000字符；二进制或不支持编码返回明确错误，不猜测正文。
- 单方案最多100个动作；单文件最多256MiB，总文件大小最多1GiB。超限在预览阶段拒绝，不静默截断动作。
- 不覆盖既有目标；复制采用独占输出与临时文件发布，移动采用目标不存在的提交方式。大复制分块校验取消；锁定文件报错，不调用shell绕过。

这些限制用于减少常见越界和误操作；运行进程仍属于当前Windows用户，不防御具有同等OS权限的恶意进程。必须在检查与最终文件动作之间保持最小间隔，并对真实文件句柄/目录身份做可实现的复核；不能把“检查后再操作”描述成完全无竞态。

## 数据、方案与状态

新增`.local/desktop/workspace.sqlite3`，不改会话或陪伴数据库结构。保存根授权、不可变方案、动作、执行任务和逐项收据；所有状态变化按事务提交。

方案包含`schema_version=1`、`plan_id`、`root_id`、`root_revision`、创建时间、规范化动作和`digest`。文件快照包括相对路径、大小、mtime_ns、文件身份与SHA256；已存在目标目录保存身份，新建目录显式列为动作。目标不能是另一项待移动源；循环交换改名、重复目标、隐式覆盖在首版直接拒绝。

审批绑定整个方案摘要、目录授权版本及文件快照，不产生永久写权限。方案有效期10分钟；确认前已有变化须重新生成预览。执行前再全量校验快照，每一步前再次核对授权、来源和目标条件。确认请求带`request_id`用于幂等；一份方案只能成功排队一次。

| 状态 | 用户含义 |
| --- | --- |
| `pending` | 可查看的预览，未授权文件修改 |
| `queued` | 已确认，等待该目录执行队列 |
| `running` | 当前任务在执行，逐项更新收据 |
| `completed` | 所有动作确认完成 |
| `cancelled` | 已停止，保留成功项与未执行项 |
| `failed` | 冲突/IO错误导致停止，展示实际成功项 |
| `interrupted` | 上次进程在文件动作期间退出，需核查记录，不自动重新执行 |
| `undone` | 经确认的逆向任务已成功恢复全部可撤销项 |

每个动作先持久化intent，再开始文件IO，完成后记录实际文件身份/哈希。收据写入失败时停止任务并标记需核查，不声称成功。每个根目录一次只能执行一个修改任务；确认并发方案须重新检查目标，不能靠旧预览假定可执行。

重启不自动重试`running`或`queued`任务，标记中断并保留证据。intent与实际文件之间的崩溃窗口可能产生不确定结果；只有身份/快照足够确认时才将其归类为已完成，其他项提示人工核查，不自动删除或移动未知文件。

撤销是另一份需要确认的逆向任务：移动将收据匹配的目标移回仍空闲的原位置；复制移除仍匹配的本产品副本；新建目录仅在仍为空且身份匹配时删除。拒绝逆向冲突，记录部分成功并停止，不把一个多文件批次声称为文件系统事务，也不承诺任意时间无条件撤销。

## 接口与进程职责

`WorkspaceService`负责目录授权、列表/搜索/读取、方案冻结与校验；`WorkspaceJobManager`负责单根队列、停止令牌、线程内文件IO和收据。二者是确定性服务，不创建新LLM或Agent Loop。

DesktopBridge增加固定`workspace`方法：`snapshot()`、`chooseRoot()`、`revokeRoot(root_id)`、`setChatAccess(root_id, enabled)`、`listFiles(root_id, relative_dir)`、`searchFiles(root_id, query)`、`readText(root_id, relative_path, start_line)`、`proposePlan(request)`、`confirmPlan(plan_id, digest)`、`cancelJob(job_id)`、`previewUndo(job_id)`、`confirmUndo(job_id, digest)`。原生目录选择及确认留在主进程。

HTTP路由限于`/workspace`、`/workspace/roots`及其固定授权/读取操作、`/workspace/plans`及其确认操作、`/workspace/jobs`及其取消/逆向预览。所有workspace路由要求本次Electron生成的随机Bearer控制令牌，主进程以子进程环境传给后端；令牌不进入renderer、模型或公共诊断。缺令牌时workspace HTTP接口关闭，避免在localhost暴露无鉴权的审批端点。此令牌不宣称防御同用户的恶意OS进程。

执行确认立即返回`job_id`，主进程/renderer轮询任务快照；网络超时不表示任务没开始，重试用同一request_id查回同一任务。HTTP请求断开不将一个正在修改文件的线程遗弃；任务由服务拥有，取消与退出走JobManager。设置重启需同时拒绝活跃文件任务，不能只检查聊天Run。

## 文件职责

- `backend/herta_agent/workspace/models.py`：严格请求和响应字段、状态枚举。
- `workspace/paths.py`：原始路径/根身份/祖先边界，Windows规则。
- `workspace/store.py`：独立SQLite授权、方案、任务、收据。
- `workspace/service.py`：浏览/读取/预览/快照校验。
- `workspace/jobs.py`：排队、取消、执行/撤销、崩溃记录。
- `workspace/tools.py`与`router.py`：同Registry工具、固定HTTP路由和控制令牌校验。
- `service/app.py`：服务生命周期/注册及权限组合，保持现有Loop。
- `frontend/electron/workspace.ts`：参数检查、固定路由、目录选择及原生确认；调整main/preload、backend-process.ts的环境传递及desktop-settings.ts的活跃任务检查。
- `frontend/shared/workspace-contracts.ts`：所有桥接字段和状态类型，避免扩大现有contracts单文件。
- `frontend/src/state/workspace-store.ts`与`components/WorkspacePanel.tsx`、`FilePlanPreview.tsx`、`FileJobHistory.tsx`：工作台数据、预览和收据；沿用灰紫Token与键盘焦点。
- `backend/tests/test_workspace_*.py`、`frontend/tests/unit/workspace*.test.ts`、`tests/e2e/workspace.spec.ts`：独立目录夹具、固定时序和真实桌面验证。

不复制Hermes上游业务代码。工程机制参考：`tools/write_approval.py:73/166`的待审提案，`agent/file_safety.py:78`原始命名空间检查与防御边界，`tools/file_tools.py:48/61`的读取输出预算，以及既有Registry/Executor。Herta自己实现不可变SQLite方案和文件收据，维持拒绝未知副作用工具。

## 必须通过的验收

1. 真实中文临时目录中选择文件，预览前后源文件/目录完全不变；取消原生确认仍不变；确认后复制/移动/改名结果与哈希一致。
2. 修改源文件、替换祖先为junction、重新创建所选根、撤销授权、目标重名、大小写碰撞和锁定文件均不能执行旧方案或覆盖新内容。
3. 重复确认、请求返回前断开和同根并发不造成重复副作用；主界面能查回真实任务状态。目录授权版本改变后旧确认被拒绝。
4. 大文件复制中停止，清理本任务的已知临时输出，保留已完成收据；后续动作不开始。设置重启和退出对活跃文件任务有明确处理。
5. 重开数据库可查看方案/收据；模拟intent写入后/文件动作后/收据写入前退出，呈现准确中断或需核查，绝不盲目自动重试。
6. 撤销正常完成；撤销前编辑目标、占用原位置、给新目录新增文件时拒绝相应动作，不覆盖或删除后续工作。
7. 离线Provider通过同Agent执行读取/方案工具，仍不能确认或实际修改文件。未开启聊天访问/撤销后读取失败；任意副作用MCP仍被拒绝。
8. 真实Electron验证目录对话框、文本预览、搜索、计划确认/取消、文件任务停止、收据、重启和撤销。测试只接触专用临时夹具，不操作用户下载目录。
9. 新增测试先失败后实现，再运行完整后端、前端单元、类型/静态检查、构建及Electron。只允许本地夹具，不调用DeepSeek/远程Embedding。
