# 语音等待和短句截断修复

2026-10-13。本机RTX3050Ti/CUDA测试；未使用远程TTS、DeepSeek或远程Embedding。

## 复现与原因

用户例句：`来了？今天想弄清什么。`。旧配置直接合成WAV只有0.74秒，本地ASR只识别“来”，所以截断发生在模型合成端，不是播放器把完整音频切掉。

固定版本的GPT-SoVITS会为短开头补一个前导停顿。原`cut5`切句后丢掉了它，当前角色checkpoint随后过早结束。并行/串行对照均产生0.74秒；保留停顿的`cut0`产生2.54秒，并包含后半句。本地ASR结果为“來了今天小弄清什麼”，有“想/小”的识别差异，不能视为逐字或主观音色评价。

旧适配器每次请求都启动、加载、退出模型；一次实测总耗时39.7秒。此前验收主要检查WAV格式与非静音，没有覆盖这类短句的正文完整性，这项验收不足已补上真实本机回归。

## 修复行为

- 使用`cut0`保留短开头停顿，前端和推理worker均保留全部文字并分成最多120字符的段，避免长句超过解码范围。
- 选择大黑塔音色时在后台准备模型及首次推理缓存，同一worker服务连续请求。空闲5分钟、切换音色或退出时释放。
- 当前段播放期间只预合成下一段；停止、录音、切换会话会丢弃过期结果，不播放旧音频。
- 界面显示生成/准备声音状态。首次启动或缓存已释放后的模型准备仍需等待，不承诺零延迟。
- 活跃请求数与驻留模型数分开，缓存空闲不阻塞音色设置；有正在合成的请求仍需先停止。
- 音色切换和语音请求共用准入锁，切换中的新请求等待设置完成再读取音色；连续空白段跳过合成，随后正文继续朗读。
- Windows worker先暂停创建、加入自有Job再恢复，取消同时关闭venv启动器和真实解释器；清理进程后再删除自有暂存WAV。文档进程的1GiB内存上限保持不变。
- Piper与faster-whisper保持原有本地接口。角色权重和参考音频未修改。

## 本机证据

完整预热实测18.49秒，准备后两次请求：

| 文本 | 合成请求耗时 | 音频时长 |
| --- | --- | --- |
| 来了？今天想弄清什么。 | 1.109秒 | 2.54秒 |
| 你好，我是黑塔。今天也要认真学习。 | 1.446秒 | 3.50秒 |

两次请求复用一个模型进程，活跃请求为0，退出后驻留进程为0。耗时受设备和系统负载影响，以上为测量结果。

失败→通过：真实短句正文覆盖、重复请求不重载、预热/空闲释放、排队取消不误杀当前请求、实际venv解释器取消、完整有界分段、预合成取消、音色切换竞态及连续空白后的正文。后端完整运行341项，其中340项通过、1项真实GPU用例默认跳过；该GPU用例已单独实际通过。前端71项、TypeScript/ESLint、Ruff及构建通过。

完整Electron24项已通过。聚焦只读审查发现音色切换竞态和空白段中断两处问题，均加入失败测试并修复；最后改动后的5项语音相关桌面回归全部通过，覆盖朗读、录音、取消、失败反馈、音色及学习设置恢复。

用户从托盘退出后，已通过原启动入口重开实际应用（04:13:13的新进程），沿用原数据。实际应用的本地HTTP接口再次生成同一句：请求2.132秒、音频2.54秒/162604字节；声音状态为已准备、活跃worker为0。这个结果包含服务接口耗时，不能替代首次模型准备耗时。
