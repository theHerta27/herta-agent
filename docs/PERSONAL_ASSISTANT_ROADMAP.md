## 交付顺序

| 里程碑 | 可拿来用的结果 | 关键验收 |
| --- | --- | --- |
| A1：桌面与磁盘只读分析，下一批 | 选目录、项目/快捷方式识别、浏览/搜索/文本读取、目录占用与重复候选报告 | 不改变任何用户文件；标明分析范围、跳过项与局限 |
| A2：受控文件工作台 | 分类预览、开发项目保护、复制/移动/改名、确认、收据、取消与条件撤销 | 中文临时目录整理→重开→撤销；不覆盖用户后续修改 |
| B：文档与快捷上下文 | 手动加入选中文字/截图；读取Markdown、PDF、Word；选择内容进入聊天草稿并显示来源 | 原文位置与提取方式清楚，失败明确；截图理解需要视觉Provider或OCR，不能把截屏当作理解 |
| C：个人知识与学习 | 独立的个人资料集合、增量索引、跨文件来源引用、Obsidian导出、学习材料 | 不混用角色索引与个人索引；新增/移除资料后检索结果一致；生成文件仍走A的审批 |
| D：可复用Skills | 成功任务→草稿→审核→版本→按需加载→效果反馈 | Skill不能扩大目录权限或绕过审批；能追溯来源任务、修改和复用结果 |
| E：主动任务和扩展 | 显式授权的定时Agent作业、多只读MCP、任务历史/取消/失败恢复 | 提醒仍不用LLM；作业有预算/范围/结果，睡眠和重启不产生重复副作用 |
| F：可选高级能力 | 按需屏幕/OCR/视觉操作、连续语音、外部服务、内容创作 | 优先API/工具；单独验收窗口焦点、共享停止、外部动作确认 |

代码协作与Live2D继续按用户原约束排除。材料中的P2清单是候选能力，不视为这次重新提升它们的优先级。现有语音/提醒按实际使用反馈改进，不重建第二个执行循环。

## 工程原则

Harness只负责模型/工具/上下文/事件；文件、媒体、调度和解析是边缘服务。确定性动作不用模型规划。新增业务先使用内置工具，MCP用于外部接入。

指定目录授权、不可变动作方案、人工确认、执行记录和撤销是共享机制的第一种实现。后续文档写入、Obsidian导出和Skill落盘沿用这个机制；外部消息/提交表单另建适合其不可逆性质的确认流程。

记忆记录事实与偏好，Skill记录方法；都可查看和修改。自动学习不等于自动执行未知脚本、修改Harness源码或永久获取权限。
