# Herta 日常陪伴 v1 本地交付

实施：2026-10-11至12。基线：`f1f6be07405682f5961dffb44ba0dae8de346f2e`，分支 `phase-6-ui`。最终源码版本以本文所在 Git 提交为准。设计见 [companion-v1-design.md](companion-v1-design.md)，执行计划见 [实施计划](superpowers/plans/2026-10-11-companion-v1.md)。

## 使用

当前机器可直接双击项目根目录 `启动离线演示.cmd`，在“日常”导入音乐、添加提醒和确认记忆，录音后编辑草稿；演示聊天是回显。真实聊天入口 `启动Herta.cmd` 沿用已有 DeepSeek 配置，发送消息会调用指定服务，本轮没有运行这个入口。

关闭窗口会隐藏并继续音乐与提醒；双击托盘或 Ctrl+Shift+H 恢复。托盘右键“退出 Herta”结束应用并清理 Python。切换离线/真实模式须先完全退出。完全退出/睡眠跨过期限后，重开或唤醒补一条到期记录，重复提醒跳过已错过的多次期限，避免通知洪水。延后重复提醒另建一次性延迟，不改变明日/下周的原定时间。

固定提醒没有模型推理费用。日常按钮直接走确定性服务；自然语言创建提醒、控制音乐或提出记忆经过同一 Agent Loop 的7个注册工具，用户可关闭。保存记忆与偏好会作为数据加入之后的新一轮模型上下文，因此在真实聊天模式下会随该轮发送到用户配置的模型服务；删除后不加入新轮。已有对话历史不会因删除记忆而改写。

## 本地语音

依赖：锁定可选 `voice` 扩展，当前准备 faster-whisper 1.2.1、piper-tts 1.8.0。模型在 `.local/voice`，公共下载由 `准备本地语音.cmd` 显式触发，运行时使用本地目录与离线环境，不传音频/聊天给下载站。

- ASR：[Systran/faster-whisper-base](https://huggingface.co/Systran/faster-whisper-base)，CPU/int8、中文识别。
- TTS：[Piper huayan medium](https://huggingface.co/rhasspy/piper-voices/tree/main/zh/zh_CN/huayan/medium)，中文单声音、22,050Hz。它不是大黑塔的官方声音，也未进行声音克隆。
- 下载时固定仓库 revision；本机 `.local/voice/manifest.json` 保存实际版本及每个模型文件 SHA256。
- 原模型卡保留在 `.local/voice/piper/zh/zh_CN/huayan/medium/MODEL_CARD`；其中数据集 License 标记为 Unknown。Piper 可选运行时来源见 [官方项目](https://github.com/OHF-Voice/piper1-gpl)。权重未提交、未制作含权重的发行安装包。

实际本地 TTS→重采样16k PCM→ASR 验证结果：“你好,我是黑塔,该休息了”，处理结束活动子进程0。录音最长60秒、最多2MB；识别文字进入当前草稿，需用户发送。切换会话/停止会取消旧请求并防止迟到结果进入新会话。朗读分段完整回答，停止或开始录音取消旧合成与播放，恢复音乐音量。

一次全量独立只读审查发现4项重要问题，并将“朗读失败缺少可见提示”从轻微提升为重要，合计5项在同一修复批次处理：

1. 工具开始事件等待期间撤销权限：执行 handler 前再次校验，固定时序后端测试从失败转为通过。
2. 等待取消IPC时被停止的朗读/录音晚启动：第一处 await 前保留 generation，两个单元用例从失败转为通过。
3. 切换会话没有暂停正在播放的朗读：会话清理停止音频并使后续分段失效，真实 Electron 先观察旧音频未暂停，再验证已暂停。
4. 等待 AudioContext 关闭期间切换会话仍启动旧识别：转录前复核会话与 generation，真实 Electron 旧请求数从1变为0，草稿保持空白。
5. 本地朗读失败静默：添加订阅音频状态的可见提示及可重试按钮，真实 Electron 注入本地HTTP503后，从没有提示转为显示错误。

上述陪伴专项桌面测试3/3通过；新增单元测试同时验证停止正在播放的长回答后不会再合成下一段。没有遗留的 `minor (deferred)` 项目，没有重复派发审查。

Windows 系统通知已接线，并将通知投递与用户“知道了”分开保存。桌面测试验收到期卡片与延后；没有把操作系统是否展示某个 Toast 当成精确投递保证。免打扰、Windows 通知权限、锁屏及系统策略会影响展示。应用完全退出期间不执行。

原始日志/截图位于 `.local/companion-*.log`、`.local/companion-*-desktop.png`。`.local` 不提交。复现全量命令沿用 README；语音扩展测试需要本地依赖和权重，可缺失跳过，当前机器已实际运行通过。生成语音UI夹具并验证本地合成/识别：`./.venv/Scripts/python.exe scripts/verify_voice.py`；之后运行 Electron E2E。

## 当前边界

本轮仅本地验收，没有 DeepSeek/Embedding API 问答、路由质量或费用评测。ASR 只以测试句和模拟麦克风验证可用，不代表已测完噪声、口音及所有设备；可编辑草稿保留人工纠错入口。

这一版交付日常陪伴闭环。主动聊天、连续语音通话、在线音乐、文件/网页自动化、个人资料导入、自动提炼可复用 Skills 仍为后续范围。Live2D 与代码协作不做。当前依赖项目目录、本机 Python/Node/模型，不是全新机器通用的安装包。

## 实施取舍与记录

- 沿用用户指定项目的当前 `phase-6-ui` 功能分支，保留调研与原始用户文档；没有额外工作树。若隔离要求发生变化，需要把本次改动移到新 checkout。
- 用原生 Windows 命令和 `.local/companion-work` 记录执行，替代技能中的 Bash 辅助脚本。代价是没有辅助脚本自动管理账本，实际命令结果与决策保存在本报告、Git和本机日志。
- 维持真实聊天/Embedding验收禁令，遵循用户最后指令；代价是自然语言工具选择和回答质量尚未测量。
- 将Windows通知描述为已接线，以应用内到期记录为验收证据；系统策略影响Toast。代价是系统通知可能被隐藏，只能在Herta内看到提醒。
- 使用本地合成测试句检验ASR，并保留可编辑草稿；没有覆盖全部麦克风、口音和噪声。代价是实际设备可能需要配置或纠正转录。
- 交付本机可运行的源码目录，模型权重保持忽略，不制作含模型的安装包；未评估全部依赖/模型的再分发和新机可移植性。代价是另一台机器需配置，并另行核查发行条件。

这些取舍没有改变用户的授权范围。所有真实模型验收限制持续有效；无推送或合并。
