# Phase 4 最小设计：可追溯、可评测的角色 RAG

状态：最终设计已确认，工程实现和离线测试已完成；真实服务效果待配置验收。用户选择独立配置的远程兼容 Embedding API，授权发送知识片段与 query；Key仅从本机环境读取，不写配置/索引/日志/测试数据。实际命令与限制见 phase-4-walkthrough.md。

## 1. 目标与不变量

用现有大黑塔材料回答角色事实、人物关系和故事事件，找到证据、返回出处、区分资料支持的内容与未知。只使用现有 corpus，不扩充外部语料，不加入项目文档或技术笔记。

正式聊天由模型主动调用 search_knowledge。主路径是 Embedding + 本地精确余弦相似度检索；不引入向量数据库或近似索引。词面 baseline 可单独用于评测，不是首版交付依赖，也不参与融合。

保留 Phase 3：soul.md 为必需运行条件，加载失败停止该轮、不降级；每 Run 一个完整人格快照。知识资料经 tool message 回填，不进入 system 或 Persona 文件。Agent Loop 不包含检索算法或角色判断。

不做 RAG 以外的 Memory、Skills、MCP、UI；不做重排、自动查询分解、爬虫、文件监听或索引后台更新。本阶段保留前台全量建库命令与聊天时异步查询的清楚分工。

## 2. 本次已整理的资料

- knowledge/herta.md：20 个 K01–K20 证据单元，人工忠实转述原快照，保留猜测、夸张、遮蔽和反转。
- knowledge/sources.json：唯一源文件及其 SHA256、原链接、各单元的原文范围。未知采集日期保留 null，不伪造。
- evals/rag/questions.jsonl：28 题，13 可回答、4 跨段、7 资料不足、4 无需检索；dev 17、check 11。
- 原始两份材料不移动或修改。整理思路和 Persona evidence 不当作角色事实入库。资料范围说明是编辑说明，不冒充原文台词。

语料和题目在索引前固定版本；评测输入与答案不得进入索引。第一版白名单仅 knowledge/herta.md，README/manifest 不向量化。此小语料足以验证链路，不代表广泛世界观覆盖。

## 3. 两条执行路径

建库：显式知识目录 → 读取白名单正文与来源 → 按证据单元/段落切分 → 生成文档向量 → 验证 → 写入新版本目录 → 发布 manifest 指针。

查询：模型提出 query → 参数验证 → 查询向量 → 同一索引全部向量精确打分 → 排序/过滤/限量 → chunks + 来源 + 检索诊断 → 既有工具回填 → 模型据证回答。

开发检查入口直接调用同一个 Retriever，绕过聊天模型输出排名和元数据，便于区分模型路由问题与检索问题。它不是 Runtime 自动检索规则。

## 4. 最小模块与接口

| 计划文件 | 职责 |
| --- | --- |
| rag/models.py / store.py | Chunk、来源、索引manifest验证类型；检索结果采用JSON字典 |
| rag/ingest.py | 显式白名单、单元识别、确定性切分、来源映射 |
| rag/embeddings.py | 文档/查询编码接口与选定服务的一个适配器，不预建多个后端 |
| rag/store.py | 版本化本地文件读写、完整性与配置一致性检查 |
| rag/retriever.py | 归一化、精确打分、排序、过滤和结果预算 |
| rag/__main__.py | 建库、inspect、eval 三类开发命令，具体参数在实现时按本设计落地 |
| tools/search_knowledge.py | query 参数、工具描述和 Retriever 调用，无重复检索算法 |
| __main__.py / config.py | 显式装配与配置；默认资源/索引路径不依赖启动 cwd |

Retriever.search(query) 返回结构化结果；模型只提供非空 query，最多 1000 字符，不能指定任意路径、模型、阈值或 k。k、阈值、结果预算由应用配置管理。

Embedding 接口区分 embed_documents 与 embed_query，以便固定所选模型的输入前缀或不同 query/document 编码模式。查询与文档必须属于同一兼容向量空间；不仅比较维度，还检查模型和编码配置指纹。

## 5. 切分与来源契约

以 `## Kxx 标题` 为语义边界，不跨证据单元拼接。先保留完整自然段；超过 600 个 Unicode 字符的正文再按句界优先切分，必要时字符兜底；只在被拆长段内部保留至多 80 字符重叠。这些是待 dev 验证的初值，600 字符不是 600 token。短单元不机械重叠，不截断标题。文档输入超出所选编码器长度限制应清楚报错，而非默默截断。

Chunk 保存 unit_id、title、正文、整理文件路径和位置、原始来源范围、源 URL、document_hash、chunk_id。chunk_id 由文档版本、unit_id 与正文偏移确定；正文完全相同时也不能误合并不同来源单元。评测以 unit_id 判断证据覆盖，避免被切分参数绑定。

规范化规则固定为 UTF-8 去 BOM、CRLF/CR 转 LF；保存规范化正文偏移和整理文件行号，原始行号来自 sources.json。manifest 同时记录输入文件字节哈希和规范化文档哈希，明确各自含义。这与 Persona 保留 CRLF 的注入规则分属不同职责，不改 Phase 3 行为。

## 6. 向量与本地索引

单个float32矩阵加chunks.jsonl和manifest.json；已新增NumPy用于精确矩阵运算，不部署服务。归一化后cosine等于向量点积，同分用chunk_id确定顺序。

校验响应数目/对应顺序、维度一致、数值有限、非零范数；索引加载再校验矩阵行数与元数据一致。文件格式使用非 pickle 数组，加载禁用 pickle。模型名相同但服务或编码方式不同也不自动兼容；manifest 记录逻辑模型/服务标识与编码配置，不保存 Key。

存储路径为项目 .local/rag 下的版本目录。先完整写出并验证新版本，再在同一磁盘替换小型 current.json 指针；Windows 下不覆盖仍被读取的矩阵文件。切换失败旧版本继续有效，失败版本不被查询；没有自动清理运行中版本的任务。CLI 启动时加载一个索引快照，进程内固定；重建后重启 CLI 才采用新索引。

文件改变或模型配置与索引不符时，明确要求重建/重新启动，不临时自动建库。原始材料不随每次查询重新解析，索引是可再生缓存，不是唯一数据源。

## 7. 检索结果与失败行为

初始 k=4；返回总正文最多 2400 字符，每条完整返回、不在返回阶段再次切成半句；超预算跳过并记录原因。按分数排序，依次去掉同 unit 且与已选片段正文区间重叠的低分候选，非重叠片段可同时保留。先用 dev 校准阈值与 k，再冻结用于 check；没有通用的“0.7 就可信”规则。

结果包含原始 query、index_id、检索方式、所用 k/阈值、返回 chunk_id/unit_id、score、正文和来源。inspect 额外展示过滤前候选与丢弃原因。score 是相似度，不是事实置信度。top-k 不保证有答案；命中返老还童资料也不代表其中包含完整公式。

工具描述明确适用于本 corpus 的事实问题，要求先查再据证回答，用实际返回的 chunk_id 引用；纯寒暄/一般技术问题无需调用。模型触发属于需要评测的行为，不通过 Runtime 猜关键词强制检索。引用核验只检查本轮实际返回的 id；引用存在不证明语义支持，仍要人工核对。

可预期 RAG 失败通过带稳定 code 和安全 message 的 ToolExecutionError 传出，由 Executor 归一为现有最外层 ok=false/data=null/error；未知异常仍是 execution_error。不把一层 ToolResult 当 handler data 再包进 ok=true，服务响应正文和凭据不能出现在错误中。

| 状态 | 处理 |
| --- | --- |
| 合法索引但无相关片段 | 成功，chunks=[]，明确 no_relevant_evidence |
| 有相关片段但问题细节缺失 | 返回相关证据；模型说明不足，不补造 |
| corpus 为空或格式无效 | 建库/装配报corpus_invalid，不伪装正常无命中 |
| 索引缺失/损坏/配置不符 | index_missing / index_invalid（或index_vectors）/ index_mismatch，不降级 |
| Embedding 超时/服务错误 | 工具失败，保留安全错误码；不自动重试或换模型 |
| 用户取消 | 沿用 Task 取消、工具结果闭合和 Session 释放 |

人格失败仍阻止整个 Run。RAG 不可用与 Persona 不同：CLI 明示知识工具不可用；角色事实检索调用返回明确失败，不冒称已据资料回答；不影响不需要检索的普通交流。工具失败不会强制锁住模型后续自然语言，这个诚实边界必须在端到端评测中检查。

超时最小方案：给 ToolSpec 增加可选 timeout；未设置沿用当前 RunSettings.tool_timeout（echo 行为不变），search_knowledge 默认 20 秒并可由应用配置；覆盖 query embedding 到结果构建。建库逐批设置独立有限期限，取消时不发布半成品。保留现有 max_steps 和每次响应最多4个工具调用，不额外预建任务调度器。

## 8. 验证与验收

工程：52 项原回归必须通过；测试来源映射、短/长中文段落、换行、确定性、空库、向量校验、模型/维度不符、破损索引、失败发布、超时/取消、工具配对与 Persona 快照不变。Windows 路径含空格/中文、目录外启动为必测。

检索：题目原文直接查询，分别记录过滤前与返回后的证据覆盖；有答案题总17个，按 unit 去重计算；跨段4题单列全部命中。资料不足7题检查输出是否越过资料，无需检索4题仅计路由。dev/check 划分与记录规则见 evals/rag/README.md。

端到端：记录实际工具查询、实际命中、最终引用与回答，逐题诊断“没查/查错/漏证据/有证据却答错”。可重复运行观察模型非确定性；不把 mock 结果当真实语义效果。模型参数、corpus/index/config 指纹和耗时写入本地报告，不记录 Key。

门槛：工程确定性检查与引用可解析性必须通过；真实检索/路由/回答逐题对照预期，失败项必须修复或明确作为未通过交付，不以“调用成功”替代效果验收。在选定模型并跑真实数据前，不编造质量成绩或最终阈值。

## 9. 已确认的远程 Embedding 边界

仅实现一个真实远程 OpenAI-compatible Embeddings 适配器，沿用 HTTPX。保留 embed_documents/embed_query 接口，不实现本机模型或同时接入多个后端。

独立环境配置 HERTA_EMBEDDING_BASE_URL、HERTA_EMBEDDING_MODEL、HERTA_EMBEDDING_API_KEY，不回退到聊天配置。可选文档/查询前缀和输入字符上限属于编码配置；服务端 token 限制仍由实际模型合约验证。Key只从环境装载到内存，排除序列化；索引仅保存服务/编码配置指纹和模型标识。用户已接受文档片段与查询出机。

本机当前没有 HERTA 环境配置，因此可以完成 mock 合约与确定性工程验证，真实建库/语义评测需本机配置后再运行。此限制不以假向量结果替代。实施中若需要改变知识范围、触发机制或向量空间边界，先询问。
