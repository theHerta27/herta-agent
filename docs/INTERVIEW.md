# 面试讲法与项目边界

## 60秒介绍

我做的是一个Python CLI Coding Agent，主要学习Claude Code的Agent Loop、工具权限和上下文管理机制，再在已有Herta Runtime上独立实现和收敛。用户指定项目目录，用自然语言提编码任务，模型自己选择搜索、读取、编辑和测试工具，Harness负责参数校验、人工确认、执行限制、错误回填和会话记录。

我验证过一条真实任务：DeepSeek定位average的空列表除零问题，读取代码与测试，经确认后修改、回读、执行3个unittest；独立检查器确认行为正确、测试未削弱。程序可以单独安装，退出后恢复会话，恢复不会重放副作用。为了控制规模，第一版只开放5个工具和Windows unittest，没有通用Shell、操作系统沙箱或多Agent。

## 最常见追问

**Agent和调用一次模型有什么区别？**

一次模型调用只能产生回答或操作建议。Agent把“模型决定下一步 → Harness执行工具 → 结果回填 → 再问模型”形成循环。`runtime/agent.py:Agent.run`是唯一循环；模型不直接执行Python函数。

**谁决定调用read_file？Tool Calling怎样发生？**

Registry把ToolSpec参数模型变成JSON Schema，Provider随请求发送给模型。模型返回名字、参数JSON和call_id。Executor查找工具并验证参数，调用handler；返回工具消息必须对应同一个call_id。工具未知、参数错或拒绝都返回结构化结果。

**为什么要把Registry和Executor分开？**

Registry描述“有哪些工具、参数是什么”；Executor决定“这次参数能否执行、怎样处理错误和期限”。便于换模型、加工具和统一限制，不需为每个工具再写一套Loop。

**权限能阻止脚本访问其他文件吗？**

不能。目录检查约束内置Read/Edit等工具，人工确认是允许执行这一调用。run_tests执行的是用户项目Python代码，仍拥有当前账号权限。没有操作系统隔离，所以我明确只对可信项目测试；不把审批称作沙箱。

**用户看完diff、点击同意后文件又被改了呢？**

Edit携带Read的SHA256，预览和实际写入都检查。指纹不同或old_text不是唯一匹配就拒绝，防止模型用旧内容覆盖新文件。多个文件不提供整体事务回滚。

**测试工具成功，为什么不能直接宣布修复完成？**

工具成功只表示运行并取得报告，报告可能是failed、no_tests或skipped。还要看实际测试状态、是否有有效断言、改动是否满足任务。演示另用未交给模型的checker检查行为并比对原测试字节；也只能证明这次小任务。

**上下文和Session有什么区别？**

Session/SQLite是完整档案，Context Engine决定本次请求摆上桌面的材料。保留系统提示、当前轮次和完整工具配对，旧轮次按预算选择，必要时程序摘录，不删除原历史。Token估算会有误差；当前完整轮次超预算就明确结束，不伪称无限上下文。

**与Claude Code压缩有什么差别？**

快照中可追踪query调用microcompact/autocompact，compactConversation/streamCompactSummary可发模型摘要请求并建立压缩边界。Herta只是程序摘录与完整轮次选择，没有实现其语义摘要、全部门控和溢出恢复。对照文件给出准确SHA、路径和未展开部分。

**为什么用asyncio？并发做了什么？**

HTTP模型请求和存储I/O可以等待而不阻塞事件循环；同步文件工作进入线程，测试有自管进程树。CLI的工具目前仍顺序执行，不能把async写法说成工具并行。取消必须等待线程/子进程收尾，不能只让界面显示“停止”。

**退出后恢复会不会重复执行工具？**

不会主动重放。已有消息与结果恢复为历史；上次进程崩溃留下的调用被标为interrupted、结果未知。新的编辑和测试需要新的模型调用及逐次确认。已经写入的文件不会因取消自动回滚；结果未知先核查。

**Provider解耦真的验证过吗？**

同一Loop可用固定demo、测试HTTP适配器和实际OpenAICompatibleProvider。已在DeepSeek真实服务验证工具闭环；不能据此保证所有兼容服务都通过。更换服务要验证Schema、正常结束标志、tool_calls和错误协议。

**你学的源码究竟是什么？**

官方文档是主要机制说明；2.1.88材料是第三方从Source Map整理的还原快照，不是官方开源仓库。查阅提交`554bc4514ebaf83ef54d95bc44f4add7272d4f46`的特定文件，逐份核对镜像字节，只读研究、不复制非开源代码、不声称读完全部分支。Python教学仓库另列MIT许可和提交，辅助理解而非冒充原实现。

**最大限制和下一步是什么？**

当前适合小型Python任务：字面搜索、单处文本替换、已有目录新建文件及unittest。没有任意Shell、pytest、自动依赖安装、跨文件事务或OS沙箱；只做过少量真实任务，没有通用任务成功率。下一步应由真实使用暴露问题后决定，优先修可靠性和验证更多代表性任务。
