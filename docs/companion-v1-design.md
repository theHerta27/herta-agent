# Herta 日常陪伴版设计

用户已于2026-10-11授权开始实施。工程参考以 `references/hermes-agent-main` 为主；Cyrene用于产品功能与交互借鉴。此次可交付范围为前一轮推荐的第一批日常陪伴能力，文件/网页助手、资料学习和自动生成Skills继续按后续路线推进。

## 交付行为

- 保留唯一Python Agent.run、Persona、Context Engine、SSE、SQLite历史及只读MCP。
- 聊天中可查询/播放已由用户导入的本地音乐、暂停、切歌、调整音量；界面显示真实播放状态，不把发出命令当作已播放。播放器按钮不用模型。
- 创建一次性或按天/周重复的提醒，查看、取消、稍后提醒。Asia/Shanghai为默认时区，模型看到当前时间。提醒到期直接通知，不请求模型。
- 关闭窗口隐藏到托盘，Ctrl+Shift+H唤出；托盘显式退出仍完整清理后端。完全退出期间不执行提醒，重开后展示未读/错过提醒，周期仅通知一次并推进到未来。
- 偏好包括称呼、音乐音量、自动朗读、免打扰时间与日常工具开关，可查看修改删除。模型提出的自由文本记忆先成为候选，由用户保存；不后台调用模型整理记忆。
- 回复可朗读并停止；按键录音，转录为可编辑输入，发送仍进入同一Agent.run。声音协调降低音乐音量，停止取消请求和播放；不承诺持续通话/VAD打断。
- 一键学习模式播放当前音乐并设置45分钟提醒，有明确实际结果。
- UI沿用现有大黑塔素材、字体和灰紫色Token，日常面板集中音乐/提醒/偏好，消息朗读按钮与录音按钮靠近聊天操作。

## 工程参考及取舍

- Hermes root AGENTS.md的窄核心原则：能力在边缘服务实现，原Agent不承担音频和时钟任务。
- Hermes cron/scheduler_tick.py 与 cron/occurrences.py：调度领取、发生次数去重、持久记录，运行与交付状态分别处理。Herta用已有SQLite生态实现事务领取与未读提醒。
- Hermes tools/write_approval.py：跨会话记忆先候选再保存，可管理；Herta明确偏好直接保存，自由文本提案待确认。
- Hermes tools/transcription_local.py与tts_tool_local.py：本地语音Provider边界。采用本地faster-whisper和Piper，依赖/模型显式准备，运行时不自动下载、不上传录音或朗读文本。
- 权限默认拒绝副作用；新增策略只允许本产品注册的明确日常工具，其他MCP/任意shell不获得授权。可随时关闭日常工具。
- Persona仍按Run冻结；偏好和记忆作为有标记的数据附加，不回写soul.md，不在每个step重建。当前时间以Asia/Shanghai生成。

## 数据及边界

- 独立companionship.sqlite3置于会话DB同目录，保存音乐条目/控制期望与实际状态、提醒发生记录、结构化偏好与候选记忆。
- 音乐只由主进程文件选择器导入，后台API经已注册音乐ID读取文件；renderer通过窄协议获取媒体，不能指定任意文件路径。
- 音乐控制有单调revision；播放器报告对应revision与实际状态，旧报告不能覆盖新操作。
- 提醒发生记录以(reminder_id,due_at)唯一，事务推进下次时间；交付先留未读，通知成功后标记，重启重投未确认提醒，允许重复通知但不丢失任务。
- HTTP/IPC参数严格校验，音频上传/输出有体积/时长上限，语音工作进程由请求拥有并可终止。缺模型清楚展示准备方法。
- 保留现有用户未跟踪设计文档和此前调研记录；原feature分支上实施，不push/merge。
