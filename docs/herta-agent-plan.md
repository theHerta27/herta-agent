## 一、产品定位

**Herta Agent 是一个以大黑塔为默认人格、面向 Windows 的个人 AI 桌面助手。**

它以参考 Hermes Agent 架构独立实现的 Python Agent Harness 为核心，通过 Tool Calling、MCP、上下文工程、个人记忆与 Skills，连接本地文件、文档、学习资料、日程提醒、语音和桌面环境。

最终目标是让 Herta 既能够自然地聊天与陪伴，也能帮助用户处理真实电脑事务，并随着长期使用积累经过确认的用户偏好、知识和任务方法。

### 核心原则

1. **实用优先。** 不为了展示技术而堆积功能，优先解决实际生活、学习和电脑使用中的问题。
2. **保留自研 Harness。** 继续使用现有 `Agent.run()`，不将 Hermes 或 Codex Runtime 直接替换为项目核心。
3. **工具与 Agent 分工明确。** 模型负责理解意图、选择工具和处理不确定问题；确定性程序负责计算、文件操作、提醒和数据持久化。
4. **权限透明。** 读取私人资料、向远程模型发送内容、修改文件、删除数据等操作具有不同权限边界。
5. **不盲目引入 Multi-Agent。** 简单任务使用工具或 Workflow，确实需要独立任务决策时才考虑子 Agent。
6. **角色体验与功能解耦。** 可以更换人格、任务角色和声线，但不应改变底层工具权限和执行规则。
7. **持续完善而非反复重构。** 基于已有源码增量开发，优先复用可靠组件，保留历史数据和测试。

## 二、当前已有基础

根据此前已核对的 `phase-6-ui` 及陪伴版交付报告，当前已经实现或具备以下工程基础：

- 自研异步 Agent Loop、Provider 抽象、工具注册与执行器。
- Context Engine、对话历史管理、上下文预算和执行诊断。
- 基于 BGE Embedding 的本地角色知识 RAG。
- SQLite 持久化、多会话、FastAPI、SSE、Electron + React 桌面应用。
- 官方 MCP SDK 的有限只读工具接入。
- 托盘驻留、快捷键恢复、基础提醒和待确认记忆。
- Piper 中文 TTS 与 faster-whisper ASR 的本地语音链路。

这些能力已经形成基础框架，但部分功能仍只有本地测试结果，真实模型路由、长期使用体验和部分硬件场景尚需实际验证。

**尚未作为成熟产品能力交付的重点：**

受控批量文件整理、通用文档转换、Obsidian 学习工作流、完整长期目标管理、自动提炼与复用 Skills、特定角色声线 GPT-SoVITS 接入、按需屏幕理解。

2026-10-12 已实现 V2.1 只读工作台：目录授权、浏览/名称搜索、文本预览、空间排行、有限重复候选、取消及历史。它仅进行本地读取与确定性分析，真实模型的文件工具路由尚未验收。

后续开发应以实际源码和运行结果为准，不因规划文档存在就将功能标记为已实现。

## 三、最终产品功能

### 1. 桌面整理与文件助手

**目标：** 让 Herta 能帮助用户整理真实 Windows 桌面及授权目录。

预期功能：

- 查看目录结构，识别普通文件、文件夹、快捷方式和常见项目类型。
- 按文件名、类型和可读取的内容提出分类建议。
- 支持文件搜索、复制、移动、批量重命名和子目录创建。
- 在执行前展示完整操作方案与冲突。
- 用户明确确认后执行，保留逐项收据。
- 支持停止剩余操作，并对符合条件的已完成操作申请撤销。

特别要求：

**默认保护代码项目、虚拟环境、Git 仓库、系统目录、启动脚本和可能存在路径依赖的文件。**

不因为桌面杂乱就自动迁移正在使用的工程项目。

### 2. 磁盘空间分析与清理助手

**目标：** 帮助用户理解磁盘空间占用，并安全释放不再需要的空间。

预期功能：

- 只读分析选定磁盘或目录的占用。
- 显示大文件、目录大小排名、重复文件候选和可识别缓存。
- 标注可能清理的对象、风险和预计影响。
- 区分“文件很大”“可能不再需要”和“可以安全清理”。
- 首次仅提供分析报告，不执行任何清理。
- 获得明确范围与对象授权后，才开放对应清理操作。

不将模型判断直接作为删除依据。

不默认清理源码、模型权重、虚拟机磁盘、实验数据、数据库或游戏存档。

### 3. 文档处理

**目标：** 用本地现有软件能力完成常见文档任务，避免为简单转换依赖付费工具。

优先能力：

- DOCX 转 PDF。
- PDF 合并、拆分、旋转、指定页面提取。
- 图片与 PDF 的常见转换。
- Markdown、TXT、DOCX 和 PDF 内容读取。
- 文档总结、信息提取、生成 Markdown 学习笔记。

优先复用 LibreOffice、pypdf、python-docx 等成熟工具，不自行开发文档排版和 PDF 引擎。

PDF 转 DOCX、扫描件 OCR、复杂表格与公式识别作为后续能力，允许尽力转换但不得承诺无损还原。

默认输出新文件，保留原始资料。

### 4. Obsidian 与学习助手

**目标：** 将 Herta 变成能够长期陪伴学习、理解和复习的智能助手。

预期功能：

- 绑定用户授权的 Obsidian Vault。
- 检索现有笔记、课程材料和技术文档。
- 整理学习笔记，生成提纲、总结及关联建议。
- 根据已有材料生成练习题和复习计划。
- 记录学习进度、已掌握内容与需要复习的知识点。
- 支持语音朗读、跟读、复述、背诵和错题复盘。

提供不同学习任务角色：

**老师模式：** 根据学习材料解释概念、提问、引导理解。

**面试官模式：** 围绕指定岗位、项目或知识主题提问、追问，并给出反馈。

**背诵模式：** 依据指定原文或标准要点进行朗读、暂停、复述和遗漏检查。

**复盘模式：** 根据用户已经学过的资料提出问题，帮助发现薄弱知识点。

这些模式共用一个 Agent Harness，不创建多个独立 Agent Loop。

其中：

- Persona 决定人格及表达风格。
- Role 决定当前任务中的身份。
- Skill 定义教学、面试、背诵等可复用方法。
- 学习数据库保存材料和进度。
- TTS/ASR 提供语音输入输出。

语音转写可以由用户纠正后再进行背诵评价，避免把识别错误当作知识错误。

### 5. 待办、目标与提醒

**目标：** 提供真正可长期使用的任务管理。

区分：

- **短期任务：** 今天、近期、具有明确截止时间的行动。
- **长期目标：** 需要持续推进的项目、学习方向和计划。
- **重复任务：** 每天、每周或特定周期的事务。

首页默认优先显示近期行动和即将到期的任务，长期目标通过独立区域查看。

支持自然语言创建、修改、完成和延期任务，但保存前需要确定日期、时间和重复规则。

定时提醒由确定性调度器负责，不需要 LLM 持续运行。

复用已经实现的提醒与托盘功能，重点补齐长期目标、任务关联、进度和用户体验。

### 6. 长期记忆与 Skills

**目标：** 让 Herta 在长期使用中逐渐积累可靠的个人上下文和可复用方法。

长期记忆主要保存：

- 用户明确确认的偏好与约定。
- 可复用的个人资料和长期目标。
- 已确认的重要学习进度。
- 与任务相关且仍然有效的历史经验。

用户能够查看、纠正、停用或删除这些内容。

Skills 保存“怎样完成某一类任务”，例如：

- 技术概念教学方法。
- 模拟技术面试方法。
- Obsidian 笔记整理方法。
- 桌面文件整理方法。
- 文档批量转换方法。

支持从已完成任务中提出 Skill 草案，但在保存或更新前应由用户审核。

**这里的自我改进指经验和工作方法的积累，不代表自动训练底层语言模型。**

Skills 不能自行获得额外文件访问或执行权限。

### 7. 随处唤起与屏幕理解

**目标：** 让 Herta 成为 Windows 中随时可访问的桌面助手。

预期功能：

- 保留托盘常驻和现有快捷键。
- 增加轻量悬浮输入面板。
- 支持用户主动附加选中文字、截图或框选区域。
- 根据获准的上下文解释代码、错误、网页内容和外语材料。
- 有视觉模型时使用多模态理解；没有时按能力使用文字或 OCR。

不默认持续录制屏幕，也不在用户不知情时读取整个桌面。

发送给远程模型的截图、文字和文件内容应当有明确提示。

### 8. 人格、声线与语音助手

**目标：** 保留默认大黑塔风格，并允许用户配置其他身份、称呼与声音。

预期设置：

- 默认 Persona。
- 用户称呼和表达风格。
- 当前任务角色。
- TTS Provider 与音色。
- 语速、音量、自动朗读选项。
- 语音输入、暂停、重复朗读与打断。

技术上继续保留已有 Piper TTS 和 faster-whisper ASR。

新增可选 GPT-SoVITS Provider：

- GPT-SoVITS 使用独立 Python 环境。
- 通过本机 HTTP API 与 Herta 通信。
- Herta 复用现有朗读接口和语音播放组件。
- 可以配置使用权明确的角色音色与参考音频。
- 不将第三方模型权重提交到 Git 仓库。

**当前大黑塔模型的特殊问题：**

用户提供的 `.pth`、`.ckpt` 与5段参考音频已规范化至 `models/voice/the-herta/v2proplus`。两组权重均已完成 `weights_only=True` 受限加载，移动前后 SHA256 一致，原 ZIP 保留。`.pth` 的 `06` 特殊文件头属于官方 v2ProPlus 格式，先前“文件结构异常”的判断已更正；只在内存中适配，原始字节未修改。[官方格式处理](https://raw.githubusercontent.com/RVC-Boss/GPT-SoVITS/main/GPT_SoVITS/process_ckpt.py)

用户已授权本机使用和整理；分发许可材料未提供。真实推理尚未验证，仍需独立环境、预训练依赖及本机语音生成验收。参考文本暂取自原音频文件名，未人工核对朗读内容；资源说明见 `VOICE_ASSETS.md`。

在确认模型能够安全、正确加载之前，不修改权重字节、不绕过加载保护、不默认打包分发该模型。

可以先独立完成 TTS 技术验证，不要求阻塞其他桌面功能开发。

## 四、总体技术架构

### 桌面交互层

Electron + React + TypeScript。

负责主聊天窗口、快捷面板、文件工作台、知识管理、学习界面、待办、音频控制和原生操作确认。

### Agent Harness 核心

Python + asyncio + Pydantic。

继续使用唯一 Agent Loop，负责：

- LLM Provider 接入。
- 模型决策与 Tool Calling。
- Tool Registry 和 Tool Executor。
- Context Engineering。
- Persona、Memory 和 Skills 的按需组装。
- 工具权限和用户审批。
- Run 生命周期、取消、错误处理、事件与诊断。

### 工具与能力层

各功能以独立服务或工具适配器接入：

- File Service。
- Disk Analyzer。
- Document Service。
- Knowledge / Obsidian Service。
- Learning Service。
- Task Scheduler。
- Speech Service。
- 语音播放与打断协调。
- Screen Context Service。
- MCP Tool Adapters。

工具不必全部是 MCP Server，也不要求每项功能都有独立 Agent。

### 持久化层

继续以本地 SQLite 为主，保存会话、任务、审批、操作收据、提醒、学习进度、记忆与 Skill 元数据。

大型文档、生成文件、音频和向量索引分别使用本地文件存储，数据库记录关联身份和必要元信息。

保持原始事实与派生摘要、记忆、模型意见分离。

## 五、实施路线

以下按依赖关系划分，不要求在一次 Codex 会话中完成全部内容。

### V2.0：巩固现有基础

**目标：** 稳定保留当前可工作的 Herta。

工作内容：

- 核实当前本地源码、分支与远程 GitHub 的差异。
- 重新确认聊天、RAG、MCP、提醒、语音和桌面功能现状。
- 保留现有对话与用户设置。
- 整理已经实现和未实现的能力边界。
- 对需要真实模型的项目安排独立体验验证。

不重写已有 Agent Loop。

### V2.1：桌面与磁盘只读分析

**状态：** 已实现；本地回归与限制详见 `READONLY_WORKBENCH_ACCEPTANCE.md`。不开放复制、移动、重命名或删除。

**目标：** 先让 Herta 看得清楚，再决定是否操作。

工作内容：

- 通过原生目录选择器授权指定目录。
- 浏览、搜索和检查桌面文件。
- 识别项目目录、快捷方式和普通文件。
- 生成桌面整理建议。
- 扫描指定磁盘或目录占用。
- 提供可疑大文件、重复文件和可能清理项的分析报告。

### V2.2：受控文件执行

**目标：** 真正完成桌面整理任务。

在此前 Codex 文件工作台设计基础上，保留必要的工程机制：

- Agent 可以提出操作方案。
- 用户可以查看和调整方案。
- 确认绑定具体文件及操作范围。
- 执行器负责真正的文件操作。
- SQLite 保存逐项收据。
- 支持任务停止、冲突检查和条件撤销。

不允许模型直接执行任意删除或任意 Shell 命令。

2026-10-12 已实现：勾选/按类型整理、不可变具体预览与摘要、原生确认、拥有式执行队列、停止、逐项收据、幂等与条件撤销。同一 Agent Loop 仅能提出方案。文件执行与只读任务互斥，保留旧数据库；尚未进行真实模型工具路由验收。

### V2.3：文档与个人知识库

**目标：** 让 Herta 能够读懂常见文件，并产生学习成果。

工作内容：

- PDF、DOCX、TXT、Markdown 读取。
- 常见 PDF 操作和 DOCX 转 PDF。
- 文档总结与内容提取。
- 扩展现有 RAG 的文档来源。
- 绑定 Obsidian Vault。
- 生成和保存结构化学习笔记。

优先打通完整的阅读、整理与保存流程。

2026-10-12 已接通文档阅读→引用检索/聊天草稿→编辑笔记→保存预览→原生确认闭环。PDF操作、真实本机DOCX排版转换及个人BGE检索已通过本地夹具验证。生成成果沿用文件收据与撤销，源文件变化或目标存在时拒绝发布；索引可移除，不删除原资料。

### V2.4：学习助手与任务管理

**目标：** 形成可以每天使用的学习系统。

工作内容：

- 老师、面试官、背诵和复盘任务角色。
- 学习资料与学习进度管理。
- TTS 朗读、复述与 ASR 转写纠错。
- 短期任务、长期目标和重复任务。
- 学习任务与提醒关联。
- 从学习记录中形成复习建议。

保留大黑塔默认人格，但允许在不同任务中切换表达角色。

### V2.5：人格、语音与记忆深化

**目标：** 让个性化能力成为完整的产品系统。

工作内容：

- 人格与称呼设置。
- 可切换 TTS Provider。
- 在模型通过来源和兼容性验证后接入 GPT-SoVITS。
- 朗读暂停、重复、停止、错误提示与音频协调。
- 完善长期记忆的查看、修改与来源管理。
- 支持生成、审核、保存和加载 Skills。

### V2.6：桌面体验与外部扩展

**目标：** 提升日常使用便利性。

工作内容：

- 轻量快捷面板。
- 用户主动共享的选中文字和截图。
- 视觉模型或 OCR 适配。
- 更多符合实际需求的 MCP 接入。
- 完善应用启动、配置和发行体验。

复杂 GUI 自动化、Live2D 和多平台消息接入不作为此阶段的强制交付项。

## 六、明确暂不追求的功能

为了避免产品再次失去主线，以下事项不作为当前必须完成的目标：

- 重写 Hermes、Codex 或其他完整 Agent Runtime。
- 为每项工具单独建立一个 Agent。
- 强制实现 Multi-Agent、LangGraph 或多种开发框架。
- 自研 Office 或 PDF 的完整底层能力。
- 默认全盘扫描、自动清理和未经批准的文件修改。
- 自动训练底层大语言模型或语音模型。
- 完整的 Unity / 游戏开发工具链整合。
- 复杂 Live2D、自动电脑操作和跨平台聊天渠道。
- 大型分布式架构或多用户服务平台。

这些可以成为后续探索内容，但必须有具体使用需求才引入。

现有 `mihoyo-agent-project` 继续作为独立的游戏研发 Agent 工程项目维护，不要求合并进 Herta。

## 七、开发与交付原则

1. 每项新功能先确认用户实际想完成的任务，再决定工具与架构。
2. 优先阅读现有源码，复用已实现能力，不重新实现同一个机制。
3. 保留原有数据和历史；涉及迁移先明确影响范围。
4. 区分本地功能测试、真实模型效果评测和用户体验测试。

## 九、最终产品完成后的典型体验

用户打开电脑，可以随时通过快捷键呼出 Herta。

Herta 能帮助用户查看和整理桌面，分析磁盘空间，处理常见文档，把学习资料整理进 Obsidian，按老师或面试官模式开展学习，朗读需要背诵的内容，并记录任务进度。

它能够记住经过用户确认的偏好，并根据实际任务经验提出可复用 Skills。

在获得授权的情况下，它可以真正执行文件操作，而不是仅仅输出建议；执行前可以查看方案，执行后可以追踪结果。

默认采用大黑塔的人格与用户选定的合法语音资源，也允许切换其他任务角色和声线。

**最终目标不是实现最多的功能，而是形成一个真正实用、人格稳定、能力可扩展、运行可靠、用户能够理解和控制的 Windows 个人 Agent。**
