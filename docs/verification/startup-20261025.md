# Windows PowerShell启动修复

基线0575be8，本轮无提交/推送、无模型请求、无PATH或Profile修改。

用户报错有两部分：`>>`表示PowerShell还在等待一条未完成的语句；中文JSON乱码则是Python UTF8输出经旧代码页读取造成。原生Windows PowerShell5.1实际复现CP936下checkout/wordcount的ConvertFrom-Json未终止字符串，65001可正常解析。

修复：prepare.py输出ASCII JSON，ConvertFrom-Json还原完整Unicode，不改任务原文。Start-CLI.ps1增加-Case checkout/wordcount，复用已有准备脚本、密钥读取和真实CLI，最多16步；不增加工具或Loop。Case与Repo/Resume/ListSessions互斥，防止无声替换目标。Demo仍明确离线回显，不会修复。结束后仅打印可复制的独立检查命令，避免拒绝操作后自动执行项目代码。Windows脚本保留UTF8 BOM。

实际验证：

- 新增4项原生测试通过，5.590秒。包含CP936/65001分别读取两种任务并与原中文逐字比较、从工作区内带空格cwd启动、实际启动CLI.cmd包装入口、普通-Repo .的离线多轮启动。
- 最终全部CLI124项通过，41.471秒；Ruff全backend/示例及2个变更Python文件格式检查通过。
- 初次启动测试将cwd放系统Temp，受限账号下.NET GetFullPath访问被拒；改用工作区.local内自建目录后通过，没有改产品路径逻辑或ACL。
- 原始日志留.local/startup-windows-red.log、startup-windows-green.log、startup-windows-final.log、startup-cli-regression.log。未假装验证过用户物理剪贴板或所有终端版本；本轮没有重新调用真实模型。

操作见[面试演示](../DEMO.md)。Claude Code标准启动方式“进入项目目录后运行claude”依据[官方快速开始](https://code.claude.com/docs/en/quickstart)；PowerShell编码差异依据[Microsoft说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_character_encoding?view=powershell-5.1)。本项目当前仍使用本地启动器，未注册全局herta命令。
