## 如实保留的失败与中断

- JSON新增测试第一次错误地把print输出与不含换行的json.dumps结果比较，造成1失败。模型根据工具反馈，仅修改自己新增测试的断言，添加应有的换行，再测通过；不是再次修复业务实现，也不是修改原有测试。轨迹和工具输出保留了失败。
- 自动审批服务额度不足导致发送no的工具调用未执行，之后两个终端会话丢失。只读核查确认旧进程已不存在，原数据库仍有running记录。用CLI原resume恢复后，旧Run被标interrupted、未决结果补为未知；模型先重新读取实际文件，再发起新调用。没有手工改数据库或无声重跑整项任务。
- 结算第一次独立checker由受限账号运行，无法读取另一账号原子替换后的演示文件，出现PermissionError；用与Agent相同的实际账号重跑通过。未改ACL或产品权限。失败日志留在.local/checkout-check-restricted.json，不当作产品修复。
- JSON模型最终回答声称缺少wordcount/__init__.py，但实际该文件从模板就已存在；证据保留原回答，不采用这条提示作为事实。这说明最终自然语言回答仍需核对实际文件。
- conflict模型只知道写入冲突，不能据其回答断言当前文件仍是2。独立核查确认实际是外部编辑后的7。
